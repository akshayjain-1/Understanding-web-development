- Validations allow us to set specific constraints or rules that determine what data users can enter into an input. When a user enters data that breaks the rules, a message will appear, providing feedback on what was wrong with the entered data and how to fix it.

## Required Validation
- We will often want to ensure specific fields have been filled in before submitting the form. To make a field required, we add the `required` attribute to it
```
<form action="#" method="get">
  <label for="user_email">
    *Email:
    <input type="email" id="user_email" name="user_email" required>
  </label>

  <label for="user_password">
    *Password:
    <input type="password" id="user_password" name="user_password" required>
  </label>

  <button type="submit">Login</button>
</form>
```
- we should always indicate which fields are required by adding an asterisk(*)

## Text length validations
- Sometimes we will want users to enter a minimum or a maximum amount of text into a field.
    - Minimum length validation: To add the minimum length validation, we give the form control a `minlength` attribute
        - minlength doesn’t imply required. “Constraint validation is only applied when the value is changed by the user.” so if the user submits without entering anything it will submit because the value was not changed by user
    ```
    <form action="#" method="get">
      <textarea placeholder="What's happening?" minlength="3"></textarea>

      <button type="submit">Tweet</button>
    </form>
    ```
    - Maximum length validation: To add a maximum length validation, we give the form control a `maxlength` attribute
    - can also combine both validators together

## Number range validations
- Just like we often need to control the length of text-based form controls, there will be many situations where we will want to control the range of values users can enter into number based form controls
- We can do this with the min and max attributes, which allows us to set the lower and upper bounds of the value entered into the form control.
- The min and max attributes only work with number-based form controls such as the number, dates and time inputs.
    - Min validation: `<input type="number" id="quantity" name="quantity" min="1" value="0">`
    - Max validation: `<input type="number" id="passengers" name="passengers" max="5" value="0">`

## Pattern Validation
- To ensure we get the correct information from users, we will often want to ensure data matches a particular pattern.
- Real-world applications include checking if a password, credit card number or a zipcode is in the correct format.
- To add a pattern validation, we give the form control a pattern attribute with a regular expression (regex) as the value.
```
<label for="zip_code">Postal / Zip Code:</label>
<input type="text" id="zip_code" name="zip_code" placeholder="12345" pattern="(\d{5}([\-]\d{4})?)" required>
```
- pattern validation to ensure a US zip code is in the correct format (5 numbers followed by an optional dash and 4 more numbers)
- The `pattern` attribute can only be used on `<input>` elements.

## Styling validations
- The `:user-valid` and `:user-invalid` pseudo-classes allow targeting form controls that have passed or failed validation, ensuring input fields remain neutral until user interaction.
```
<form action="#" method="get">
    <label for="email">Email</label>
    <input type="email" id="email" name="email">

    <label for="website">Website</label>
    <input type="url" id="website" name="website">

    <button type="submit">Submit</button>
</form>

// CSS
input:user-valid {
  border-color: green;
}

input:user-invalid {
  border-color: red;
}
```
