- You might think that the majority of a developer’s work involves writing code. However, in reality, a significant amount of time is spent on **reading code**.
- This includes code written by other team members, code written by people who are no longer part of your team, and even code that you wrote two weeks ago but may not remember much about.

## Clean Code
- functions and variables should be named clearly.
- The indentation and spacing should follow a consistent and logical pattern.
- camelCase is a naming convention that allows writing multiple words together without spaces or punctuation
- A good function or variable name is descriptive. Variables of the same type ideally follow a consistent naming system. 
- Use searchable and immediately understandable names
- Choose a way to indent and stick to it.
- Generally, your code will be easier to read if you manually break lines that are longer than about 80 characters.
- it might be tempting to have comments that explain everything the code is doing. This is generally not a good practice. The code must be mostly self explanatory
- Ideally, comments do not provide pseudocode that duplicates your code. Good comments explain the reasons behind a piece of code.
